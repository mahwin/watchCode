# CLAUDE.md: 시니어 반전 숏드라마 제작 키트

이 폴더는 유튜브 '시니어 반전 숏드라마' 쇼츠를 기획하고 제작하는 작업 공간이에요.
Claude Code는 아래 파이프라인대로 에피소드를 만들고, 결과물을 `episodes/`에 저장해요.

## 먼저 읽을 파일
1. `analysis.md`: 레퍼런스 채널 분석(잘된 영상 vs 안된 영상). **모든 판단의 근거예요.**
2. `prompts/01~06`: 단계별 프롬프트. 각 프롬프트의 규칙과 출력 형식을 그대로 따라요.
3. `examples/ep001_taxi.md`: 완성 예시. 품질 기준이에요.

## 파이프라인

| 단계 | 프롬프트 | 산출물 (`episodes/epNNN/`) |
|---|---|---|
| 1. 주제·제목 | `prompts/01_topic.md` | `episodes/backlog.json`에 후보 누적 |
| 2. 대사 대본 | `prompts/02_script.md` | `script.json`, `script.md` (사람이 읽는 버전) |
| 3. 캐릭터 고정 | `prompts/03_characters.md` | `characters.json` |
| 4. 컷 분할과 프롬프트 | `prompts/04_shotlist.md` | `shots.json`, `shots.md` (표 버전) |
| 5. 썸네일·업로드 | `prompts/05_thumbnail_upload.md` | `upload.json` |
| 6. 검수·편집 | `prompts/06_qc_edit.md` | `qc.md` (검수 체크리스트, 사람이 채움) |

## 작업 규칙
- **Claude Code가 직접 프롬프트의 역할을 수행해요.** 외부 LLM API를 호출할 필요가 없어요. 각 프롬프트의 `<role>`, 규칙, `<self-check>`를 지키고 `<output-format>`대로 파일을 써요.
- 에피소드 번호는 `episodes/` 안의 마지막 번호 + 1이에요 (ep001은 예시로 예약).
- 새 주제를 기획하기 전에 `episodes/index.md`의 기존 주제를 읽고 겹치지 않게 해요 (`{{USED_TOPICS}}`).
- 에피소드를 완성하면 `episodes/index.md`에 한 줄을 추가해요: `| 번호 | 제목 | 장소 | 갈등 축 | 상태 |`
- 2단계 대본은 `<self-check>` 7개 항목을 통과해야 다음 단계로 넘어가요. 통과 여부를 `script.md` 맨 아래에 표시해요.
- 4단계의 MODE는 사용자가 지정해요. 지정이 없으면 물어보고, 답이 없으면 **MODE B(이미지 + TTS, 저비용)**로 진행해요.
- 이미지와 영상 프롬프트는 영어로, 대사와 자막은 한국어로 써요.
- 실존 인물·기업·브랜드는 쓰지 않아요. 실존 배우를 닮게 하는 묘사도 하지 않아요.
- 생성 툴의 워터마크를 제거하는 방법은 다루지 않아요. 워터마크가 있으면 편집할 때 자막과 로고 위치만 피해요.

## 자주 쓰는 요청 예시
- "주제 후보 20개 뽑아줘" → 1단계만 실행해서 `backlog.json`에 추가하고, 상위 5개를 요약해요
- "backlog 3번으로 에피소드 만들어줘, MODE A" → 2~5단계를 실행해요
- "ep003 대본에서 반전을 더 세게" → `script.json`을 수정하고, 4~5단계를 다시 생성해요
- "이번 주 업로드분 5편 한 번에" → 1단계에서 점수 상위 5개를 골라 2~5단계를 반복해요

## 이미지·영상 생성 (선택)
- Higgsfield MCP 같은 생성 도구가 연결돼 있고 크레딧이 있으면, 사용자의 확인을 받은 뒤 다음 순서로 생성할 수 있어요.
  `characters.json`의 시트 이미지 → 승인 → `shots.json`의 컷 이미지 (캐릭터 레퍼런스 포함) → 검수 → 영상
- 생성 전에 반드시 예상 비용(get_cost)을 사용자에게 알려요.
- 연결된 도구가 없으면 프롬프트만 출력하고, 사용자가 외부 툴(Gemini, Flow, Kling 등)에 붙여 넣어요.
